# Kinetics-calibration study

Can the ADM1 kinetics of a biogas plant be recovered from routine plant
measurements? This folder holds the code that answers that question by
calibrating a **known** truth: the benchmark series ship the true kinetic
factors they were generated with, so recovery can be *measured* instead of
argued about.

It is also the benchmark for the optimisers in this repository — all five of
them are run head to head at an equal budget of forward simulations.

## What is tested

| # | Question | Answered by |
| --- | --- | --- |
| **F1** | Can the kinetics be determined from the measurements at all? | `run_study.py calibrate` → `analyze.py --section possible` |
| **F2** | Which kinetics can be determined well, which cannot? | `run_study.py screen` → `analyze.py --section identifiability` |
| **F3** | How many parameters should be calibrated at once? | `run_study.py calibrate --preset count` → `analyze_count.py` |
| **F4** | How many days of measurements are needed? | presets `length` / `powell_length` → `analyze.py --section length` |
| **F5** | Which optimiser is most accurate, which most efficient? | preset `shootout` → `analyze.py --section methods` |
| **F6** | Does an extra FOS/TAC lab measurement help? | `--fostac` runs → `compare_fostac.py`, `score_fostac_prediction.py` |

The written results — tables, figures and the discussion — are **not** in this
repository. They stay with the study report in
`PyADM1ODE_estimate/experiments/kinetics_calibration/` (`report_de.tex`,
`results/`). This folder contains only the code needed to reproduce them.

## Why the benchmark can answer this

Each series was generated by perturbing all 26 ADM1 kinetics with a
multiplicative `lognormal(0, 0.25)` factor and recording 60 days of hourly noisy
sensors (`Q_gas, Q_ch4, Q_co2, pH, TS`) plus the noisy substrate feed. The
factors are stored per series, so unlike a real plant the answer is known.

The harness reproduces the generating simulator **exactly**: given the true
kinetics and the true initial state it returns the stored states bit-for-bit
(`rtol 1e-10`) and a chi-square of ~1.0 against the noisy measurements. The only
error source left is therefore the kinetics themselves, which is what makes a
clean identifiability verdict possible. `test_fastsim.py` guards this.

## Requirements

* Python ≥ 3.10 with NumPy and SciPy.
* **`pyadm1`** (PyADM1ODE) — the ADM1 model.
* **`pyadm1ode_estimation`** (PyADM1ODE_estimate) — the example plant
  (`build_multi_stage_plant`) and the observation plumbing. The study rebuilds
  the *generating* plant, so this is a hard dependency, not a convenience.
* **`pyadm1ode_calibration`** (this repository) — the optimisers under test.
* `torch` — only for the FOS/TAC channels (`--fostac`); everything else runs
  without it.

On the development machine all three repositories are installed editable into
the `biogas_torch` conda environment.

Always set `OMP_NUM_THREADS=1`. The ADM1 right-hand side is small, so BLAS
threads only fight the process pool and serialise it.

## The dataset

### Where it is found

The benchmark lives in `PyADM1ODE_estimate` and is **not** copied here. It is
located automatically, in this order (see `paths.py`):

1. `$PYADM1ODE_BENCHMARK`, if set.
2. The installed `pyadm1ode_estimation` package — in an editable install its
   `__file__` points into the source checkout, so the dataset is at
   `<repo>/datasets/benchmark`. This is what makes the default case work
   without any configuration.
3. A sibling checkout: `../PyADM1ODE_estimate/datasets/benchmark`.

Every entry point also takes `--dataset PATH` to override it. Check what was
resolved with:

```bash
python paths.py
```

### How it must be structured

The directory must contain `loader.py`, `test.npz` and `meta.json` — those three
names are what identifies a directory as the benchmark.

`loader.load_test()` must return a **list of per-series dicts**. With `T = 1441`
(60 days, hourly, endpoint included) the study reads these keys:

| Key | Shape | Used for |
| --- | --- | --- |
| `measurements` | `(T, 5)` | The objective. Columns in this order: `Q_gas`, `Q_ch4`, `Q_co2`, `pH`, `TS`. |
| `feed_noisy` | `(T, 5)` | Substrate flows [m³/d]. The *only* feed the calibrator is given. |
| `feed_true` | `(T, 5)` | Tests only — the exactness proof needs the unperturbed feed. |
| `states` | `(T, 41)` | `states[0]` is the initial state handed to the calibrator; the full array is the truth the harness is verified against. |
| `kinetic_factors` | `(26,)` | The true multiplicative factors. The reference of the whole study. |
| `regime` | scalar string | Operating mode, used to group results (`stable_low`, `low_high`, `stable_high`, `oscillating`). |
| `fostac`, `fostac_true` | `(T, 2)` | Optional, only needed for `--fostac`. Column 0 FOS [mg HAc/L], column 1 TAC [mg CaCO₃/L], stored **hourly** so any sampling frequency can be selected. |

`test.npz` must additionally carry `kinetic_keys` — 26 strings in **exactly**
the order of `fastsim.KINETIC_KEYS`. If the order differs, every factor is
silently attached to the wrong kinetic; `test_fastsim.py` checks it first.

The series must come from the plant that `fastsim.build_plant()` rebuilds
(`build_multi_stage_plant`, digester `primary`, `k_dec_ac = 0.02`). A dataset
from a different plant will load, but the exactness the study rests on is gone.

### Results directory

Sweeps write JSONL to `./results` by default. Override with `--results PATH` or
`$KINETICS_RESULTS` — point it at the report's results directory in
`PyADM1ODE_estimate` to re-derive the published tables without recomputing
anything:

```bash
python analyze.py --results ../../../PyADM1ODE_estimate/experiments/kinetics_calibration/results
```

## Running

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
cd experiments/kinetics_calibration
```

**1. Screening first.** It defines the `top<k>` parameter sets every sweep
refers to, and answers F2/F4 on the information side on its own — one Jacobian
instead of hundreds of searches.

```bash
python run_study.py screen --preset main --workers 8
```

**2. The sweeps.** All of them are resumable: re-running skips tasks already in
the output file. That is also how the two window sweeps are chained — `length`
repeats what `shootout` already did at 10 and 30 days, so writing both to the
same file computes only the 20- and 60-day windows the second time.

```bash
# F5 + F1: all five optimisers at 10 and 30 days
python run_study.py calibrate --preset shootout --workers 14 --out calibration_main.jsonl
# F4: adds the 20- and 60-day windows
python run_study.py calibrate --preset length   --workers 14 --out calibration_main.jsonl
python run_study.py calibrate --preset powell_length --workers 14 --out calibration_main.jsonl

# F3: how many parameters at once (budget scales with the parameter count)
python run_study.py calibrate --preset count --workers 14

# F6: the same count sweep with the lab measurement, weekly and hourly
python run_study.py calibrate --preset count --fostac --fostac-every-days 7 \
    --out calibration_count_fostac7d.jsonl --workers 14
python run_study.py calibrate --preset count --fostac --fostac-every-days 0.041667 \
    --out calibration_count_fostac1h.jsonl --workers 14
```

The sweep prints one line per finished task
(`chi2 start->final (truth ...) | log-err start->final`), so a run is readable
while it is still going.

**3. Tables.**

```bash
python analyze.py --out report.md          # F1, F2, F4, F5
python analyze_count.py                    # F3
python analyze_count.py --file calibration_count_fostac7d.jsonl
python compare_fostac.py                   # F6, information side
python score_fostac_prediction.py          # F6, prediction side
python bounds.py                           # the search bounds, as a table
```

`compare_fostac.py` needs two screening runs to compare, produced with
`--screen-out`:

```bash
python run_study.py screen --preset main --screen-out screening_base.json
python run_study.py screen --preset main --fostac --screen-out screening_fostac.json
```

**Tests.**

```bash
python -m pytest test_fastsim.py -v
```

### Presets

| Preset | What it is for | Rough cost |
| --- | --- | --- |
| `smoke` | Plumbing check — 2 series, 2 methods, 10 days | minutes |
| `shootout` | F5: all five optimisers, 10 and 30 days | ~2 h on 14 workers |
| `length` | F4: Nelder-Mead + DE over all four window lengths | ~2.5 h |
| `powell_length` | F4: Powell at 20 and 60 days, on the *legacy* flat search box so the runs stay comparable with the sweep they extend | ~1.5 h |
| `count` | F3: `top3 … all26`, budget scaled per parameter | ~3 h |
| `wide` | All 26 parameters and the realistic unknown-`x0` case. Implemented but not part of the published results | expensive |
| `main` | `shootout` over eight series instead of four | ~4 h |

## Speed

The benchmark plant is a three-stage cascade, but all five sensors sit on
`primary` and the cascade is one-directional — the downstream stages cannot
influence anything observed, yet they cost ~12× the runtime because their
stiffer trajectories dominate the BDF solver. `fastsim.build_plant(prune=True)`
drops them: a 60-day simulation falls from ~180 s to ~15 s with **bit-identical**
observables. Without that, this study would not be runnable.

## What is used from `pyadm1ode_calibration`, and what is not

The package contributes exactly one thing: the optimiser implementations in
`calibration/optimization/optimizer.py` (via `create_optimizer`), which are the
subject of F5. Forward model, objective, screening and scoring are implemented
here on purpose:

* **`core/simulator.py` — `PlantSimulator`** reduces the substrate feed to
  `np.mean(Q, axis=0)` and holds it constant. The benchmark's entire signal is
  the load changes (6 phases, 5 switches), so a constant mean feed would erase
  exactly what makes the kinetics identifiable. Every calibrator in the package
  routes through it, which is why `InitialCalibrator` / `OnlineCalibrator` are
  not used either. `fastsim.ForwardModel.simulate` imposes the schedule step by
  step instead.
* **`analysis/sensitivity.py`** collapses each output series to its mean before
  differencing, so the post-switch transients that carry the information are
  averaged away, and its indices are not scaled by sensor noise — so they cannot
  say whether an effect is above the noise floor, which is the whole of F2.
* **`analysis/identifiability.py`** has `correlation_with={}` as a literal
  placeholder — there is no collinearity analysis — and its
  `is_identifiable = max_sensitivity >= 1e-6` classifies essentially everything
  as identifiable.

`screening.py` therefore implements the Brun et al. (2001) measures directly:
noise-scaled central-difference Jacobian, `delta_msqr` importance, collinearity
index `gamma`, and Fisher-information standard errors.

## Layout

| File | Content |
| --- | --- |
| `paths.py` | Locates the benchmark dataset and the results directory |
| `fastsim.py` | Pruned forward model, log-factor parameterisation, sensor sigma, FOS/TAC readout |
| `problem.py` | Objective, start points, budget, recovery metrics |
| `bounds.py` | Literature-based per-parameter search bounds and priors |
| `screening.py` | Jacobian, Brun importance + collinearity, greedy identifiable subsets |
| `methods.py` | The `pyadm1ode_calibration` optimisers behind one signature |
| `run_study.py` | Stages, presets, process pool, JSONL results |
| `analyze.py` | F1, F2, F4, F5 tables |
| `analyze_count.py` | F3 tables |
| `compare_fostac.py` | F6, Fisher-information side |
| `score_fostac_prediction.py` | F6, prediction side |
| `test_fastsim.py` | Guards the exactness claims the study rests on |

## Metrics

* **`log_err`** — `|ln(f_hat / f_true)|`. 0.22 = off by 25 %, 0.69 = off by a
  factor of 2. Reported only over the parameters a run was allowed to move.
* **`start_dist`** — the same distance at the start. A final error that does not
  fall below it means calibration learned nothing, however good the fit got.
* **`chi2_final` vs `chi2_truth`** — the verdict-maker. `chi2_truth` is the best
  fit reachable with the *active* parameters at their true values and the rest
  frozen at the start. A search that fits as well as that while the parameter
  error stays high has hit an **identifiability** limit, not an optimiser limit.
* **`chi2_truth_all`** — all 26 kinetics at the truth: the noise floor,
  ~1.0 by construction.
* **`chi2_holdout`** — fit over the days after the calibration window. Note that
  the window differs per run (a 10-day run is scored on days 10–60, a 30-day run
  on 30–60), so this is an overfitting check, not a comparison across windows.
